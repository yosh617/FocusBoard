# FocusBoard UI刷新 — Codex実装ガイド

## 1. 作業の目的

時計と円形タイマーを主役にした、勉強中に邪魔をしないUIへ刷新する。既存の基本機能、保存形式、タイマーの正確性、端末内完結、アクセシビリティを維持しながら、画面の階層と操作の開始・完了・戻り先を明確にする。

この文書がUI刷新に関する現在の方針である。過去のデザイン検討を現在仕様として再利用しない。

## 2. Reference lock

### 参考資料

- [Refero UI style reference](https://styles.refero.design/style/0fd67ec5-7e9c-4ca9-b368-5d9c7388477a)
  
  白いPaper、薄いHairline、CanvasとSurfaceの三段階、幾何学的なサンセリフ、静かな境界線、機能に応じたカードとpill。

- [Audio-Technica | Connect](https://apps.apple.com/jp/app/audio-technica-connect/id1410663056)
  
  機器設定画面のように、現在地・選択状態・次の操作が一目で分かる整理感を参考にする。FocusBoardの時計・タスク・タイマー向けに適応し、ブランドや画面を複製しない。

### 固定する方向

- Primary direction: 明るい機器設定ワークベンチ。背景画像は主役として残し、操作面は不透明な白の面で切り分ける。
- Preserve: ほぼ白の操作面、黒に近い本文、細い境界線、幾何学的なサンセリフ、短い見出し、選択状態が明確なpill。
- Borrow only: ReferoのCanvas → Surface Alt → Paperの面階層と、Audio-Technica Connectの設定項目を順番に進める整理感。
- Role rules: `--accent`は選択中、フォーカス、進捗、補助的な操作状態に使う。主要な開始・保存ボタンはインク色で安定させ、時計色とタイマー色は表示内容の色として分離する。赤は削除・破壊的操作・エラーだけに使う。
- Media strategy: 背景画像は既存の内蔵画像・ユーザー画像を使用する。UIは写真や装飾グラフィックを追加せず、既存の細線SVGアイコンを機能表示に限定して使う。
- Reject: ガラス表現、背景ぼかし、カードの入れ子、過大な角丸、差し色の二重化、絵文字、意味のない左アクセント線、装飾目的のグラデーション、画面幅の小さい環境での横長ボタンの乱立。

### UIトークン

```css
--color-canvas: #f5f5f5;
--color-paper: #ffffff;
--color-surface-alt: #fafafa;
--color-ink: #0a0a0a;
--color-ink-soft: #171717;
--color-mid-gray: #737373;
--color-hairline: #e5e5e5;
--color-danger: #e7000b;
--radius-control: 10px;
--radius-pill: 18px;
--radius-panel: 16px;
```

トークンの意味を別用途へ流用しない。カードは操作や情報のまとまりに必要な場所だけに置き、設定行は面と区切り線を基本にする。

## 3. 画面別の操作契約

各画面には、主操作を1つ、補助操作を少数、終了または戻る操作を1つ置く。見出し・ラベル・一般的な細線SVGアイコン・選択状態で意味を伝え、説明文を増やして補わない。

| 画面 | 開始 | 主操作 | 終了 / 戻る |
|---|---|---|---|
| ホーム | 時計を見る、タスクまたはタイマーを選ぶ | 開始 / 再開 / 一時停止 | タイマー終了、設定またはタスクを閉じる |
| タイマー設定 | 方式 → 時間 → タスク | 開始 | 収納、設定を閉じる |
| タイマー実行中 | 残り時間と進捗を見る | 一時停止 / 再開 | 終了、タイマー設定へ戻る |
| タスク | 表示先を選ぶ | タスク追加 / タスク開始 | 詳細から一覧へ戻る、ドロワーを閉じる |
| 設定 | カテゴリーを選ぶ | そのカテゴリーの変更 | 設定を閉じる |
| セッション完了 | 結果を確認する | 休憩、続行、完了のいずれか | 閉じる、タスク一覧を開く |

狭い画面では、リスト選択とタスク内容を同時に詰め込まない。横向きではナビゲーションと内容を分け、縦向きでは表示先選択 → タスク画面の順にする。

## 4. サブエージェント運用

サブエージェントは、独立した問題を並列に解くことで速度または品質が上がる場合だけ使う。メインエージェントが設計、インターフェース、最終判断、統合、全体検証を担当する。

### 実装依頼に必ず含める項目

- 目的
- 担当範囲
- 変更してよいファイル
- 変更してはいけない範囲
- 入出力と既存インターフェース
- 完了条件
- 検証方法

### ファイル所有権

- 同じファイルを複数エージェントが同時に編集しない。
- 共有CSSや共通型はメインエージェントが所有する。必要な変更は報告させて統合する。
- 実装前に対象ファイル、caller、callee、型、既存テスト、類似実装、プロジェクト規約を確認する。
- UI実装を委任するときは `gpt-5.6-luna`、reasoning `high` を使う。`gpt-5.6-sol`にはファイル編集をさせない。

### 完了報告

```text
## Result

### Changed
- 変更ファイルと内容

### Reason
- 重要な設計判断

### Verification
- 実行コマンドと結果

### Remaining issues
- 未解決事項、担当外の懸念
```

実装後はメインエージェントが必ずdiff、インターフェース、エージェント間の矛盾、不要変更を確認する。大きな変更では、実装担当とは別のレビュー担当にコードを変更させず問題点を列挙させる。

## 5. Contextとドキュメントの運用

- 最初に `docs/INDEX.md` だけを入口として読む。
- 必要な文書、対象コード、直接のcaller / callee、型、テストの順に読む。
- 全リポジトリ、全ドキュメント、無関係な履歴を一括で読まない。
- コード探索はSembleで検索してファイルと行を特定してから直接読む。全出現箇所が必要なリテラル検索だけ`rg`を使う。
- 現在仕様と調査履歴を分ける。同じ仕様を複数文書へコピーしない。
- 設計判断は決定台帳に、調査の試行錯誤はhistory / investigationsに置く。
- 一度取得した情報は必要な箇所だけ再確認し、全文を読み直さない。

## 6. 検証ゲート

### 機能・実装

- `npm test`
- `npm run typecheck`
- `npm run build`
- 可能なら `npm run lint`
- `endAt` と `Date.now()` に基づくタイマー進行を維持する。
- localStorage、IndexedDB、AudioContext、Service Workerの失敗時も起動可能にする。
- 保存データの検証、既存versionの移行、既存テストを壊さない。

### UI・アクセシビリティ

- 1180×760と780×493で、ホーム、設定、タスク、タイマー実行中、完了状態を確認する。
- 主要ボタン、見出し、戻る、キャンセル、状態ラベルが画面内に残ることを確認する。
- キーボードのフォーカス、Escape、フォーカス復帰、タッチとApple Pencil操作を確認する。
- 色だけで状態を伝えず、role、label、text、アイコンを確認する。
- `prefers-reduced-motion`、safe area、縦横、iPhone、PCを確認する。
- スクリーンショットとアクセシビリティスナップショットを実際の操作後に確認する。初期表示だけで合格にしない。

## 7. UI刷新の決定台帳

| 決定 | 根拠 | 実装上の扱い |
|---|---|---|
| 不透明な白い操作面 | Refero style / ユーザー要求 | `background`、drawer、設定行、timer surfaceはsolid surface。backdrop blur禁止。 |
| 白・薄灰・黒の面階層 | Refero style | Canvas / Surface Alt / Paperを使い、境界線はhairlineに限定。 |
| 選択・操作状態の経路を統一 | ユーザー要求 / Audio-Technica Connectの整理感 | UI選択・フォーカス・進捗は`--accent`、開始・保存はインク色。時計・タイマー・タスクのテーマ色をUI chromeへ流用しない。 |
| 角丸を抑えた階層 | ユーザー要求 / UI評価 | control 10px、pill 18px、panel 16px。設定行をカード化しない。 |
| 画面内の操作契約 | 引き継ぎ資料 | 開始、主操作、戻るを見出しと配置で追えるDOMにする。 |
| 背景画像は主役として維持 | FocusBoardの製品目的 / 引き継ぎ資料 | 背景は既存機能を使い、白い操作面が必要な情報だけを覆う。 |
| 装飾を減らし細線SVGを機能表示に限定 | Refero style / 既存UI規約 | 絵文字、偽イラスト、意味のないstripeを追加しない。 |

## 8. 今回の修正履歴

ユーザー確認で見つかった表示上の問題と対応を、次回のUI実装でも参照できるように記録する。

| 指摘 | 対応方針 | 確認ポイント |
|---|---|---|
| 大画面でタスク画面の下部が横にはみ出す | タスクドロワー内の操作領域を可変幅にし、横向き・狭い高さでも主要操作を折り返す | 1180×760、780×493で追加・期限・優先度・タグが画面内に残る |
| 低い画面高でタスクランチャーの補助情報が下へ分離する | タイマー設定を圧縮する画面高では、テキストを隠し、件数とタスクアイコンを一つの小型操作面にまとめる | 780×493でランチャーが分離・はみ出ししない |
| タイマー設定の小見出しが多い | 「方式」「モード」「時間」などの説明用見出しを削り、選択UIと値だけで意味を伝える。アクセシブルな名前は残す | 初見で方式→モード→タスク→時間→開始の順が追える |
| ホームの設定アイコンが崩れる | 絵文字や不安定な文字アイコンを使わず、標準化した細線SVGの歯車にする | 設定ボタンのSVGが欠けず、ラベルと一体で表示される |
| 設定画面の「現在のカテゴリー」が冗長 | 表示用のカテゴリー説明を削り、タブと現在の設定項目だけを残す | 余分な説明文がなくてもタブの選択状態が分かる |
| 差し色が画面ごとに青・ピンクへ分裂する | UI chromeの選択・フォーカス・進捗・補助状態は`--accent`へ統一。時計色・タイマー色・背景固有色は独立させる | UI差し色を変更した後、設定タブ・タスク選択・プロジェクト・進捗の色が同じになる |
| 非表示背景の管理UIだけ雰囲気が違う | カード風の装飾をやめ、他の設定行と同じhairline区切り・余白・開閉記号に合わせる | summaryの左右余白、開閉状態、復元ボタンが周囲と揃う |
| 「保存色」が表示されず全て青に見える | 保存色という概念を廃止し、8色のパステル系推奨テーマ色を全カラーピッカーで表示。各swatchは`--color-picker-swatch`を直接参照する | 8色がそれぞれ異なる色で表示され、ラベルも「推奨テーマ」になる |
| 設定項目の文字が枠ぎりぎり | disclosureのsummary/bodyに横方向の内側余白を追加 | 見出し、range、ボタンの文字が枠線から離れている |
| タスク画面が大画面でも狭い | デスクトップではドロワーをビューポートに合わせて最大940pxまで広げ、ナビゲーションと本文の幅を分離する | 1920px幅で本文と下部操作が右端からはみ出さない |
| 設定タブの選択色がタスクテーマ色に引っ張られる | カテゴリータブなどのUI chromeは`--accent`を優先し、タスク固有テーマ色を混ぜない | ピンクの差し色を選んだ場合、背景タブもピンクで選択表示される |
| カラーピッカーの枠が二重になる | 設定グループ内では外側のカラーピッカー装飾を無効化し、セクションの枠だけを残す | UIの差し色・タイマーの色ともに一つの枠に見える |
| レポート集計欄の下端が丸い | レポート内セクションの外周radiusを外し、上部と同じ直線の区切りにする | 集計欄の下の枠線がフィレットにならない |
| 背景設定やタスク画面の一部操作がタスクテーマ色で固定される | 設定画面の共通操作、背景選択、背景調整ボタン、一覧のホバー・選択・完了操作、レポート期間、フォーカス輪郭を`--accent`へ接続する。タイマーの専用表示色だけは分離する | UI差し色を変えると操作先の画面も同じ色になり、旧ピンクや青が混ざらない |
| タイマー設定の枠が多い | 外側のステップ枠を外し、方式・モード・タスク・時間を一枚の設定面と最小限の区切りで整理する | 参照画像のように視線が選択→時間→開始へ流れる |
| 時計だけでなくカレンダー風の日付も使いたい | 日付表示を標準／カレンダーから選べる設定を追加し、時計・日付の個別表示切替は維持する | 時計なし、カレンダーのみ、時計＋カレンダーを組み合わせられる |
| タイマー設定とタスクランチャーが重なる | タイマー設定中は詳細ランチャーを一時的に隠し、ホームドックからタスク操作へ入れるようにする | カレンダー表示時や低い画面高でも日付・開始ボタンと重ならない |

## 9. スクリーンショット評価の記録

スクリーンショットは、初期表示だけでなく、設定・タスク・タイマー実行中など実際の操作後の状態も対象にする。評価は次の順で行う。

1. 1180×760で、白い操作面・背景・ドロワー幅・下部操作の収まりを確認する。
2. 780×493で、主要操作が隠れず、文字やボタンが横にはみ出さないことを確認する。
3. 設定の差し色を変更し、共通UIの選択状態が同じ色へ変わることを確認する。タイマー固有色は別設定として扱う。
4. 設定カテゴリー、背景管理、推奨テーマ色を開き、見出しの量・余白・色見本の実表示を確認する。
5. 検証環境で日本語フォントを確認し、豆腐文字が出ていないことを確認する。

合格条件は、主要操作の視認性、横幅・高さの収まり、差し色の一貫性、日本語の可読性、既存テストとproduction buildの成功である。

### 今回の実測結果

- `1180×760`: タイマー設定、時計、タスクランチャー、ホームドックが画面内に収まり、タイマー設定の小見出しは表示しない状態を確認。カレンダー表示中のタイマー設定では詳細ランチャーを隠し、日付との重なりを防ぐ。
- `780×493`: タイマー設定の主要操作と開始ボタンが残り、設定中の詳細タスクランチャーが重ならず、ホームドックからタスクへ入れることを確認。
- 日本語: システムパッケージの導入権限がないため、検証時のみWindowsの`Noto Sans JP` / `BIZ UDゴシック`等をfontconfigの検索対象へ追加し、豆腐文字がないことを確認。アプリ本体へ端末依存のフォントパスは追加しない。
- 色: UI差し色は`--accent`を共通経路にし、時計色・タイマー固有色は独立設定として残す。推奨テーマ色は8色を個別に描画できることを確認。
