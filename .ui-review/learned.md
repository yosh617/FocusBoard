# UIレビューで分かったこと

## セッション履歴

- 履歴を50件で打ち切る場合、見出しに総件数だけを出すと一覧との差が分からない。表示直前に最新50件までと伝え、総数と一覧上限を同時に把握できるようにする（集中レポート / 2026-10）。

## 今日のタスク

- 空状態を未完了件数だけで分岐すると、完了済みタスクが残る日に空状態の案内が消える。完了済みの開閉と空状態は独立して表示する（今日一覧 / 2026-10）。
- 固定された操作欄とスクロールする一覧を並べるときは、親と子の両方でスクロールバー幅を予約しない。画面幅別に上下の端を測り、一覧と固定欄の左右端を同じ基準にそろえる（今日一覧 / 2026-10）。

## 設定のリセットと削除

- 開いた設定の開閉行に `border-bottom` と疑似要素の区切り線を併用すると、同じ位置に線が重なって太く見える。開いた状態ではどちらか一方だけ描く（設定 / 2026-10）。
- 部分リセットと全削除を同じ強さのボタンで縦に並べると、危険度と対象範囲を押す前に比べにくい。個別リセットは小さなグループにし、削除操作は別見出しと対象説明で分ける（設定 > データ / 2026-10）。
- 設定初期化やタイマー状態の削除は、名称だけでは保持されるデータが分からないため、実行前確認で変更範囲と保持範囲を示す。
- 削除行だけ赤字にすると、設定内の共通行ボタンから浮いて見える。対象範囲の説明と確認画面があるなら、一覧行は中立な共通スタイルにし、警告色は実行直前に限定する（設定 > データ / 2026-10）。
- 設定内の操作を区切り線と文字だけで見せると、ほかの枠付きボタンとの一貫性がなく、押せる領域も伝わりにくい。共通の中立な枠・背景・角丸・hoverを使う（設定 > データ / 2026-10）。

## タスク追加とレポート

- クイック追加に任意のメタデータを常時表示すると、一覧より入力UIの方が場所を取る。タイトル入力を基本状態にし、期限や見積もりは明示操作で開く。
- 選択期間の集計と年次ヒートマップを同じ見出し/順番に置くと対象期間を取り違える。期間サマリーを先に示し、年次グラフには独自の対象期間と合計を付ける（集中レポート / 2026-10）。

## 選択状態の輪郭

- 選択中ボタンに枠線と内側/外側の影を併用すると、輪郭が二重に見えてフォーカス表示とも混同しやすい。選択は枠線と背景色で示し、キーボードフォーカスは `:focus-visible` で独立させる（共通選択コントロール / 2026-10）。
