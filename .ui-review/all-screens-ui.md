# FocusBoard 全画面デザイン監査と改善方針

対象: ダッシュボード、タイマー各状態、タスク・プロジェクト、集中レポート、バックアップ、設定、共通入力部品と確認ダイアログ。
確認日: 2026-10-09

## 評価の前提

- 実画面で確認: 1280×720 のデスクトップ表示。タスク一覧、タスク詳細、レポート空状態、バックアップ、設定の背景・表示・タイマー・データを確認。
- アプリの状態分岐と操作要素は各画面コンポーネントを読んで補完。保存データを書き換える操作（タイマー開始、削除、リセット、インポート確定）は行っていない。
- iOSの参考画像7枚とAppleの設定画面の考え方を比較軸にした。Refero連携ツールはこのセッションで見つからず、直接参照できていない。
- モバイル・タブレット実機幅のスクリーンショットは未取得。下記のレスポンシブ項目はコード上の画面構成からの提案で、実画面での適合判定は未完了。
- 既存のUI学習メモを適用: 履歴上限の明示、完了済みと空状態の独立、リセット範囲の分離。

## 改善方針

### 優先順位

- **P0 — 判断を誤らせる・完了を妨げる:** #23（空レポートの優先順位）, #28–29（復元方式と影響の事前提示）, #34（削除範囲の確認）, #38（保存/権限エラーからの復帰）。
- **P1 — 日常操作の摩擦を下げる:** #16–19（クイック追加と詳細編集の密度）, #22–26（期間レポートと履歴）, #30–33（設定行の整理、色付きCTAを中立化）。
- **P2 — 画面間の一貫性と狭幅対応:** #1–8（タイマー表示階層）, #9–15（タスク分類・空状態）, #35–40（共通ポップオーバー、ダイアログ、モバイル検証）。

### 参考画像との違い

- 参考画像の設定は白地に大きな設定行と余白、淡い帯のグルーピングで、項目ごとのカード枠を強調していない。FocusBoardの現状は選択中の背景サムネイル枠、丸い大ボタン、複数のカード/パネルが重なり、設定が「設定一覧」より「操作パネル」に見える。
- 参考画像のタスク一覧は行が白い面に整列し、状態色は完了チェックと小さな再生アイコンに限られる。FocusBoardのタスク追加欄は設定群が常時出るため、タスク本文より入力ツールバーの存在感が強い。
- 参考画像のレポートは期間指標と月間カレンダーが一つの読み順にまとまる。FocusBoardでは年次ヒートマップが上部を占め、週/月選択の集計が縦に分離するため、選択期間と図表の関係を一目で把握しにくい。
- ただし参照画像はモバイルアプリ、FocusBoardはデスクトップ中心の画面であり、密度やナビゲーションをそのまま移植せず、余白・枠線の弱さ・色の役割を参考にする。

### 1. 設定画面をAppleの設定アプリに寄せる

- カードや太い枠で各行を囲まず、白い面に設定行を置き、カテゴリ間は背景差または余白、行間は細い区切り線で表現する。
- 選択中のボタンは青/ピンクの塗りを避け、中立の薄いグレーとチェック/選択マークで伝える。スイッチ、実際のテーマ色、危険操作だけは意味のある色を残す。
- アップロード・エクスポート・再読み込みを巨大なCTAボタンとして見せない。設定項目と同じ高さの行、右側の控えめなアクションへ。
- リセットと削除を視覚的に分離し、削除は別見出し、対象説明、確認ダイアログの順で段階をつける。

### 2. タスク追加を一覧の一部に戻す

- 初期状態はタイトル入力＋追加だけ。期限、予定回数、優先度、タグ、プロジェクトは「詳細を追加」で必要な場合に開く。
- 追加フォームが縦長一覧を押し下げないよう、入力後に閉じる/縮む。空状態時は作成欄を目立たせる。
- 今日の完了タスク開閉は、未完了0件の案内や追加操作と独立させる。

### 3. レポートは選択期間を主役にする

- 日/週/月の選択と期間を上部にまとめ、主要サマリーをすぐ下に置く。
- 年次ヒートマップは下位の補助情報とし、記録0件では空状態を優先する。
- 集計→推移→プロジェクト/タスク別→履歴の順を各期間で揃える。数値の単位と対象期間は見出し直下に置く。
- 履歴上限は全件数と表示件数を明記し、もっと見る導線を設ける。

### 4. タイマーを視覚階層の基準にする

- タイマーの主表示は維持する。設定の詳細を必要時だけ開き、実行時は残り時間・現在のタスク・一時停止/終了の判断を優先する。
- 超過/完了画面では、次の推奨操作を一つ強調し、記録への反映を事前に説明する。
- ミニ表示でも時間と状態は維持し、操作ボタンはタップ領域を確保する。

### 5. 共通の視覚ルール

- 枠線は入力欄、ポップオーバー、選択範囲など境界が必要な要素に限定する。通常行・情報ブロックは余白と薄い区切り線で整理する。
- プライマリ色は「いま実行する主操作」に限る。選択状態、ナビ、ボタン、危険操作に同じ強い色を使わない。
- 空状態、0件、権限未許可、保存不可、読み込み失敗は通常表示の縮小版ではなく、それぞれ復帰方法を持つ状態として設計する。

## 今回は直さないもの

- メインタイマーの意匠は既存方針を維持し、今回は形状や配置の大幅変更を提案しない。
- 実色を選ぶカラーピッカー、状態を示すスイッチ、削除確認の危険色は色の意味があるため残す。
- デスクトップで意図的に分割されているタスクナビゲーションは維持し、狭い幅では別のナビゲーション挙動を設ける。
